# ハッカソン提出用 CM動画 構成案（Sikurepi / 尺 1:55）

規定「2分以内」に対し本編115秒。狙いは「機能紹介動画」ではなく「テレビCMの画づら」にすること。

このドキュメントの本体は **3章（画づらのパターン）と 6章（カット表）** で、それ以外は補足。数値（自炊回数のしきい値、図鑑の種類数など）はテロップに入れる前提で書いていない。確定してから差し込む。

---

## 1. 狙い

審査員が2分後に覚えて帰るものを3つに絞る。

1. レシートを撮るだけで在庫ができる
2. 在庫と気温から、AIがその日の一皿を出す
3. 作るほど記録が育つ（ランク・図鑑）

物語は1本道。「余らせて捨てた → 撮る → 提案される → 作る → 記録が育つ → ランクが上がる」。機能の羅列にしない。

CMで触れないもの：Supabase同期、課金、Capacitor、コミュニティ。尺を食う割に一目で伝わらない。末尾のスペック表示に1行入れるだけにする。

---

## 2. 画づらを8種類に分ける

「左にスマホ、右にテキスト」はCMの基本形だが、これだけで2分もたせると必ず飽きる。8つのパターンを用意して回す。

### L1 — 実写フルブリード（引き）

画面いっぱいの実写。キッチン、冷蔵庫、食卓。**人は手元と後ろ姿だけにして顔は映さない**。役者を用意せずに生活感だけ出せて、かつ素人くさくならない。テロップは下1/3の帯に置く。

使う場所：冒頭の課題、締めの食卓。

### L2 — スマホ左／テキスト右（王道）

左40%に縦持ちスマホ（実機フレームのモックに画面をはめ込み、Y軸に少し傾けて影を落とす）。右60%に見出し1行と補足1行。背景は淡い単色＋うっすら食材イラスト。

使う場所：機能紹介の基準形。ただしこれを基準にしつつ、後述のルールで散らす。

### L3 — スマホ右／テキスト左（反転）

L2の鏡像。背景色を1段変える。**L2の直後には絶対に置かない**。間に必ず別のレイアウトを挟む。

### L4 — UIクローズアップ（寄り）

スマホのフレームを外し、UIの一部だけを画面いっぱいに。実写の指が入ってタップ・スワイプする。テロップは足さず、アプリの文言をそのまま読ませる。

使う場所：「撮る」「作った！」のような、動詞のカット。引き（L2/L3）の直後に寄りで入れると画が締まる。**指が入るカットがあるかどうかで、CMっぽさが決定的に変わる。**

### L5 — スマホ複数枚（量を見せる）

3〜5枚のスマホが奥行きを持って並び、横へスライドして次々入れ替わる。1枚ずつの内容は読ませない。「こんなに入っている」の一言で処理する。

使う場所：週間献立、機能ダイジェスト。

### L6 — 分割（条件 → 結果）

左右2分割。上に共通の条件、下に別々の結果。仕切り線は一度だけ動かす。

使う場所：気候連動（暑い日／寒い日）。**この1回に絞る**から効く。

### L7 — モーショングラフィックス（抽象）

UIから完全に離れ、黒またはブランド色のホリゾントにイラスト素材だけを置く。ランクバッジ、食材アイコンの群れ。

使う場所：ランクブロック。ここだけ世界観を変えるので、CMの「山」になる。

### L8 — 白ホリゾント＋ロゴ

真っ白にロゴとタグラインだけ。**冒頭の名乗りと締めの2回だけ**。3回使うと安く見える。

---

## 3. 飽きさせないための4つのルール

1. **同じレイアウトを連続させない。** 例外は冒頭の課題ブロックだけ（L1を続けて、世界観を作る時間にする）。
2. **引きと寄りを交互にする。** L2/L3（引き）の次はL4（寄り）、その次はまた引き、という往復を基本にする。
3. **世界観を変えるのは1回だけ。** L7の抽象表現を2か所に分けると、どちらも印象に残らない。ランクブロックに集約する。
4. **同じL2でも、背景色・テキストの出方・スマホの角度を変える。** 同じレイアウトを3回使っても、この3つが違えば別の画に見える。実際のCMがやっているのはこれ。
   - テキストの出方の例：下からスライド／左から1語ずつ／中央でフェード＋わずかに拡大
   - スマホの角度の例：正面／Y軸に少し／手に持たせる

---

## 4. つなぎ（トランジション）

基本はカット（瞬間切り替え）。ディゾルブは課題ブロックの中だけで使う。

- **動きで繋ぐ** — 前カットで指が左へスワイプ → 次カットが左から流れ込む
- **モノで繋ぐ** — 食材アイコンが画面外へ飛ぶ → 次カットに同じアイコンが入ってくる
- **色で繋ぐ** — 前カットの支配色を次カットの背景色に引き継ぐ
- **白フラッシュ** — 全編で1回だけ（ランク到達）。多用すると安くなる

---

## 5. リズム

前半はゆったり、後半で詰め、最後にまた落とす。

| 区間 | 1カットの長さ |
| --- | --- |
| 掴み・名乗り | 長め |
| 機能紹介の前半 | 標準 |
| 機能紹介の後半 | 短く詰める |
| ランクブロック | また長めに戻す（動きで見せるので、切らない） |
| 締め | 静止に近づけて終わる |

## 9. 撮影・制作

### 実機画面（C〜G）

1. `npm run dev` で起動し、Chrome のデバイスモード（iPhone 14 Pro / 393×852 / DPR 3）で表示する。
2. デモ用データを仕込む。データは localStorage が正（`src/lib/storage.ts`）なので、DevTools のコンソールから在庫・履歴・自炊回数を直接注入できる。ランクバッジを高いレベルで映したいカットでは `total_cooked` を上げておく。
3. 60fpsで収録し、編集時にカットごとに速度を変える。
4. L2/L3のスマホモックは、収録した画面を実機フレーム画像にはめ込んで作る。

### 実写（A・B・C-1・I-1）

台所・冷蔵庫・食卓・手元だけ。**顔を映さない**方針なので、撮影は1人でできる。三脚固定、自然光。

### モーショングラフィックス（H）

- **推奨：HTML/CSSの1枚ページを作ってブラウザを画面収録する。** `public/ranks/` のPNGをそのまま読めて、ランク名としきい値もコードから引ける。修正が速い。
- 編集ソフトで組む場合、バッジ10枚の配置とカウンターの同期を手作業で合わせる手間がかかる。
- 生成AIはバッジの形が変わるので、この用途には使わない。冒頭の実写カットの代替には使える。

### 仕上げ

- BGMは商用利用可を確認したものを1曲。A-3で入れ、H-5の無音を挟み、I-2でフェードアウト。
- 字幕は全編に焼き込む。会場で音が出ない前提で作る。

## 10. 未決事項

1. **「Sikurepi」の読み**（ナレーション②⑩で発音する）
2. **アスペクト比** — 16:9（スクリーン投影）か 9:16（スマホ提出）。9:16だとL2/L3が成立しないので、その場合は「上にスマホ・下にテキスト」に置き換える設計が必要
3. **ナレーションの言語** — 日本語音声＋英語字幕か、日本語のみか
4. **テロップに入れる数値** — 自炊回数のしきい値、図鑑の種類数、食品ロスの統計。統計を出すなら出典と年度をテロップに入れる
5. **Hの矢印の向き** — 指定どおり上（Lv.1）から下（Lv.10）。昇格の体感は下から上のほうが素直だが、到達点で止める絵としては指定どおりのほうが読ませやすい
6. **末尾のURL/QRの宛先**
