# ハッカソン提出用 CM動画 構成案（Sikurepi / 尺 1:55）

提出規定「2分以内」に対し、本編 **1分55秒（115秒）** で設計する。5秒の余白は、冒頭の無音と末尾のロゴ静止に使う。

このドキュメントは撮影・編集の作業台帳として使う。カット表の「素材」列はすべてこのリポジトリ内の実ファイルを指しているので、そのまま編集ソフトに読み込める。

---

## 1. 設計方針

審査員が2分後に覚えて帰るものを3つに絞る。

1. **レシートを撮るだけで在庫ができる**（入口の摩擦がゼロ）
2. **在庫・気温・体質から、AIがその日の一皿を出す**（提案の質）
3. **作るほど記録が育つ**（10段階ランク／図鑑）＝継続の仕掛け

逆に、CMでは触れない要素を先に決めておく。Supabase同期、課金（Plus）、Capacitorのネイティブ化、コミュニティ機能は、尺を食う割に「1回見て理解できる絵」にならないため、末尾のスペック表示で1行触れるだけにする。

物語は1本道にする。「余らせて捨てた」→「撮る」→「提案される」→「作る」→「記録が育つ」→「ランクが上がる」。機能紹介の羅列にしない。

## 6. 撮影・制作手順

### 6-1. 実機画面（C〜G）

1. `npm run dev` で起動し、Chrome のデバイスモード（iPhone 14 Pro / 393×852 / DPR 3）で表示する。
2. デモ用データを仕込む。アプリのデータは localStorage が正（`src/lib/storage.ts`）なので、DevTools のコンソールから在庫・履歴・自炊回数を直接注入できる。ランクバッジを高いレベルで映したいカットでは `total_cooked` を上げておく。
3. 収録は OS 標準の画面収録か OBS。60fps で撮り、編集時に必要なカットだけ速度を変える。
4. レシート撮影の実写小窓（C-1）だけはスマホ実機で別撮りする。

### 6-2. モーショングラフィックス（A・H）

Hブロックはアプリに存在しない画面なので作る必要がある。選択肢は3つ。

- **(a) HTML/CSS＋アニメーションの1枚ページを作り、ブラウザを画面収録する** — `public/ranks/` のPNGをそのまま読めて、しきい値やランク名もコードから引ける。修正が速い。**推奨。**
- (b) After Effects / Canva などの編集ソフトで組む — 品質は出せるが、10枚のバッジ配置とカウンターを手作業で合わせる手間がかかる。
- (c) 生成AIで作る — バッジの形が変わってしまうため、この用途には向かない。冒頭Aブロックの実写風カットには使える。

### 6-3. 仕上げ

- BGMは商用利用可のライセンスを確認したものを1曲。0:08で入れ、1:40の無音を挟み、1:55でフェードアウト。
- ナレーションは合成音声でも成立する構成にしてある（無音が多く、間で持たせる設計）。
- 字幕は全編に焼き込む。審査会場で音声が出ない可能性を前提にする。

## 7. 未決事項（判断が必要）

1. **「Sikurepi」の読み**。ナレーション②⑩で発音するため、カナ表記を確定させる。
2. **冒頭Aブロックで食品ロスの統計値を出すか**。数字を出す場合は、農林水産省などの公表値を出典・年度つきでテロップに入れる。出典なしの概数は入れない。
3. **アスペクト比**。16:9（スクリーン投影向け）か 9:16（スマホ提出向け）か。9:16なら実機画面が主役になるのでカットの構図が変わる。
4. **ナレーションの言語**。日本語音声＋英語字幕にするか、日本語のみか。
5. **Hブロックの矢印の向き**。指定どおり「上（Lv.1）から下（Lv.10）へ降ろす」で組む。ただし昇格の体感は「下から上へ昇る」ほうが素直なので、H-1でバッジ列を上下反転（上=Lv.10, 下=Lv.1）して矢印を昇らせる案も検討の余地がある。到達点で止める絵としては指定どおりの案のほうが読ませやすい。
6. **末尾のURL/QRの宛先**。本番デプロイ先か、GitHubリポジトリか。
